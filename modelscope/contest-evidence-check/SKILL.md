# 数据库比赛提测证据检查

用于用户已经指定的比赛仓库及题目。将题面要求转换成可验证的提交清单，避免空 main、错误基线和未提交修改导致提测失败。

## 读取规则

先读取当前官方题面与仓库说明，确定允许的代码基线、必需产物和评分方式。将规则来源与读取日期记录到清单。题目要求 GPU、指定模型或指定开发工具时，核对真实运行记录；不能把安装成功、静态检查或模拟输出当作实际参与。

## 检查代码身份

运行随附脚本：

```bash
python scripts/check_submission.py --repo /path/to/repo --base BASE_COMMIT --candidate HEAD --output submission-check.json
```

`BASE_COMMIT` 必须来自已核实的题面。脚本只读 Git 元数据，不切分支、不提交、不推送。浅克隆缺失祖先时输出“无法确认”，不要直接判定合规；按用户授权获取必要历史后重试。

清单须包含完整候选 commit、基线 commit、祖先关系、当前分支及未提交文件。若用户要求提交工作区修改，先实现并验证，再创建提交；测试必须对应最终提交。不要将 URL 中的令牌或环境变量值写入材料。

## 核对运行证据

逐项记录：要求、验证命令、输入/数据版本、退出码、实际结果、日志路径、对应 commit。性能对比同时记录基线与候选的设备、依赖、数据规模、质量门槛和重复次数。区分功能通过、性能达标、尚未运行；没有证据的条目标为待验证。

## 交付

提供题目到分支及 commit 的映射、必要提交文件、已验证结果与阻塞项。用户手动提测时仅提供填写步骤，不自行提交。平台判分前不宣称满分；根据实际失败记录定位问题，不修改测试预期或编造工具使用记录。

示例请求：“检查这个仓库的 AMD 提测版本是否基于规定冻结提交，并列出尚缺的测试证据。”
