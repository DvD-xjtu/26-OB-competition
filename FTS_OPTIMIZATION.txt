The official benchmark, corpus, SQL, timing code and scoring baseline are unchanged.

Changes and rationale
- IK validates/decodes each UTF-8 character once on supported collations, retaining the original fallback for invalid input and other collations.
- Immutable dictionary ranges use binary search only after their ordering and non-overlap are verified; otherwise first-match linear lookup is retained.
- Per-call and per-scanner word maps do not require locks. Their ownership stays private; shared dictionaries retain their synchronization.
- TOKENIZE without explicit options initializes the existing built-in defaults directly, avoiding a JSON formatting/parsing round trip. Explicit options retain validation.
- Bulk index scans retain bounded word-map storage and stream one reusable output row instead of allocating a large row object for every token. Token bytes and copied document IDs live until the next document. The ordinary DML path remains unchanged.
- Natural-language membership-only retrieval avoids evaluating a direct BOOL expression once per matching document.
- A limited derived table whose sole observer is a root COUNT(*) can omit implicit relevance sorting/scoring and unused projected columns. The latter prevents unnecessary base-table lookups. Explicit order, value aggregates, outer filters, numeric score consumers, grouping/distinct/window/side effects, ties/percent limits and other modes remain excluded.

Correctness
Release build succeeded. 636 tokenizer reference cases, 177 defaults/options/collation/error cases, 234 aggregate/score/ranking/DML/transaction reference cases and 372 limited-count/control cases passed. Plan assertions confirm no relevance calculation or index-back for the eligible count-only shape, while value/filter controls retain relevance.
60 ordinary and 42 long-document/LOB/string-key/rebuild construction cases passed, plus 12 complete physical posting comparisons across bulk and incremental construction. These compare real primary key, token, frequency and document length in both inverted and forward indexes. The unmodified official tokenize_function mysqltest passed.
Bulk and newly inserted indexes can have different BM25 scores before compaction: the existing average-length estimator scans major SSTables only and otherwise uses its default of 10. Cross-layout tests therefore assert complete posting and hit equality, and separately report score differences. Numerical score regressions are covered by the 234 same-layout reference cases.
