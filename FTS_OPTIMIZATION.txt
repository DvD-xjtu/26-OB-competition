FTS optimization: first measured iteration

Changes
- IK processors receive the already decoded character and category directly.
- Sorted non-overlapping IK chains use an inline array instead of a new hash table per segment.
- Already-lowercase ASCII tokens avoid the English normalizer's case-fold allocation.
- Natural-language scalar aggregates with a direct boolean MATCH predicate can use membership-only retrieval when all expression uses are boolean. Ranked/limited queries, numeric score uses, numeric thresholds, OR-only/NOT filters, boolean search, ES search and boosted search retain scoring.
- Membership-only DaaT initializes only required state, allocates its skip vector, avoids BM25 statistics, and emits a positive membership value. No persisted search result cache or benchmark-specific constants are used.

Evidence and correctness
EXPLAIN before showed calc_relevance=true even for COUNT(*) with only boolean MATCH. After shows false for eligible aggregates; ranked queries retain true.
216 IK smart/max_word document cases match the original binary, including token frequencies and long segmented inputs. Extended corpus: 324 IK/BENG cases passed. Official tokenize_function mysqltest passed unchanged. 234 aggregate/score/ranking/threshold/update/delete/transaction queries matched the scoring reference. Regression scripts are in unittest/storage/fts and use separate local test databases.

Second iteration
- Share immutable built-in IK dictionary wrappers and pinned cache handles across parser instances; publish only after all three dictionaries initialize successfully.
- Classify each IK character after one Unicode decode.
- Use a contiguous lowercase buffer and alphanumeric scan for ASCII BEng documents under supported UTF-8 collations; retain the existing pipeline otherwise.
- 636 tokenizer cases match the pre-change reference, including four concurrent clients immediately after server restart. Official tokenize_function mysqltest passed unchanged.

November 4, 2026 — batched index builds, IK token ranges and membership scans

The reference is the team's 1e2296b31 submission (8.919/50 on the platform).
The candidate engine is f62558718. The historical team best at the start
of this iteration was 15.347/50 at 9f45ebb09.

Index build. Sampling a 20,000-document reference run showed the content-only
IK ALTER spending most of its time filling the inverted and forward indexes.
Their backfills can use different snapshots. Each still reads its own snapshot.
A scan now reuses bounded per-document frequency buffers. It emits batches
within a single source document for supported binary document IDs. Heap
integer IDs use the scalar backfill path. Compatible two-column posting keys
can use the engine's order-preserving sort encoding.

Tokenization. IK arbitration now operates on sorted candidate ranges and uses
contiguous prefix states and a cursor for emitted tokens. Range lookup uses a
binary search only when both dictionary endpoint sequences are monotonic.
Validated UTF-8 ASCII and unified ideographs need one classification pass.
The stopword prefix filter is derived from the built-in dictionary. It only
rejects impossible pairs of ASCII letters and defers all other cases to the
original collation-aware comparison.

Query. EXPLAIN EXTENDED of the reference showed a relevance sort and table
lookup for a view with LIMIT whose parent only counts rows. The guarded rewrite
omits that sort and base-column projection. Score-free inverted scans read
document IDs, and short posting lists are merged in batches using the existing
ID comparator. Queries that read a score or depend on the identity or order of
selected documents keep their original ordering and scoring requirements.

from 2.321 s. The platform best remains 34.387/50 at 32f56b9f0.

The next kernel b2afe95cc indexes verified first-character pages of immutable
dictionary ranges. A page must be wholly covered by its original first
matching range or wholly absent, otherwise it uses the existing comparison.
It also handles SQL NULL optional parser properties consistently with omission.

This kernel adds one bounded default BENG result entry per worker, private
to one session identity. Every call still evaluates arguments and validates
the parser. Eligibility is limited to exactly two arguments, the built-in
default BENG parser, no properties or warnings, supported UTF-8 collations,
and printable ASCII input of at most 512 bytes. The exact input bytes,
collation, parser version and session identity must match. It retains at
most 2048 raw binary JSON bytes. Hits copy those bytes before repacking a
new result for the current expression context. This is execution-time
result reuse, and is separate from the character-routing optimization.
IK dictionaries and noneligible inputs continue through normal evaluation.
